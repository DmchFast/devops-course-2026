# Git vs SVN — сравнение

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

**В Git** ветка - это своего рода указатель на определённый коммит. Он весит несколько байт и создаётся мгновенно. При создании новой ветки файлы не дублируются. Все ветки используют одно и то же хранилище объектов, различаясь лишь ссылкой на текущий коммит. Поэтому веток можно создавать сколько угодно и переключаться между ними за доли секунды.

**В SVN** ветка - это физически скопированная директория на сервере (`svn copy`). Все файлы дублируются в новое место в репозитории. Это требует ресурсов, времени и взаимодействия с центральным сервером через сеть. Чем масштабнее проект, тем больше времени и затрат уходит на создание ветки.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

**Нет, в классическом SVN сделать коммит без интернета нельзя.**

SVN - централизованная система контроля версий. Репозиторий один и находится на сервере. Разработчик имеет доступ только к локальной рабочей копии (working copy), и все изменения фиксируются на центральном сервере с помощью команды `svn commit`. Без подключения к серверу коммит становится невозможен.

В Git - у каждого программиста есть **копия всего репозитория** со всей историей. Изменения вносятся локально, а для отправки требуется только `git push`, что делает Git удобным для работы в любых условиях, будь то поезд, самолёт или место с нестабильным интернетом.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- **Legacy-проекты.** Если кодовая база годами живёт в SVN и всё отлажено, миграция на Git может быть дороже, чем продолжать работать как есть.

- **Госсектор и банки.** В таких системах часто предъявляются строгие требования к централизованному управлению, разграничению прав доступа к различным каталогам и проведению аудита. SVN, с его моделью «один сервер — все права сосредоточены на нём», лучше соответствует этим регламентам.

- **Большие бинарные файлы без частых изменений.** Хотя Git LFS решает проблему, в некоторых проектах с тяжёлыми ассетами (архивы, дизайн-макеты) SVN остаётся удобнее.

- **Простая линейная история без ветвления.** Если команда не использует ветки и предпочитает работать напрямую с основной ветвью, то SVN оказывается более простым вариантом, не требующим знания распределённой модели Git.

- **Частичный checkout.** В SVN есть возможность загрузить только определённую поддиректорию из большого репозитория, в то время как в Git для этого используется менее удобный метод sparse-checkout.

Сейчас для **новых проектов** практически всегда выбирают Git.
